# chabadpedia-family-trees · עצי משפחה לחב"דפדיה

כלי שעובר על ערכי האישים ב[חב"דפדיה](https://chabadpedia.co.il), מחלץ מהם קשרי משפחה עם המשפט והמקור שתומכים בכל קשר, בודק אילו משפחות כבר יש להן עץ באתר, ומייצר קוד ויקי לתבניות `עץ משפחה` ו`עץ משפחה לאדם אחד` עם קישורים פנימיים לכל אדם שיש לו ערך.

**מצב הפרויקט:** הצינור רץ מול האתר החי דרך GitHub Actions (שבע ריצות מלאות עד כה). כ-6,600 דפים נמשכו מעץ הקטגוריות "אישים", מהם כ-5,500 דפי אישים; מהם חולצו כ-33,000 קשרי משפחה, ונבנו כ-740 עצים (עץ ראשי לכל קטגוריית "משפחת X" ולרכיבים גדולים נוספים, ועצי ענף "צאצאי X" למשפחות גדולות) – כולם בגודל של העצים הקיימים באתר (עד 63 מרצפות רוחב). מול 61 דפי העץ שכבר קיימים באתר, ל-35 מהמשפחות יש כבר עץ מלא, ל-170 בערך יש כיסוי חלקי (בעיקר דרך עצי בית הרבי), ול-230 בערך אין עץ בכלל. התוצאות של כל ריצה נמצאות בענף `results`. העצים עדיין בבדיקה ידנית – יש טעויות חילוץ (שמות שחוזרים בין דורות, דפים שמונים בני משפחה בלי קישור) שמתוקנות ריצה אחרי ריצה, ושום דבר לא הועלה לאתר.

## מה מקבלים

לכל משפחה:

* `output/trees/<שם>.wiki` – התוכן לדף תבנית (`תבנית:עץ משפחת X`), כולל `<ref>` שהועתקו מהערכים, קטגוריות ו-`noinclude`.
* `output/preview/<שם>.html` (ו-`.png` עם `--png`) – תצוגה מקדימה שמדמה את התבנית, לבדיקה בלי להעלות.
* `output/review.html` – דף בדיקה: כל קשר, המשפט שממנו הוא נלקח, הערך, המקור, רמת ביטחון ודגלים ("ללא מקור", "הוסק", סתירות), וסטטוס מול עצים שכבר קיימים באתר.
* `output/ancestors/<שם>.wiki` – עץ אבות לאדם אחד (עד 3 דורות אחורה), בשתי גרסאות: הגריד הכללי, ותבנית `עץ משפחה לאדם אחד`.

שום דבר לא עולה לאתר אוטומטית. פקודת `upload` היא הרצה יבשה כברירת מחדל.

## התקנה והרצה

צריך פייתון 3.10 ומעלה. הליבה משתמשת בספריית התקן בלבד.

```bash
git clone https://github.com/Transit-Freak/chabadpedia-family-trees
cd chabadpedia-family-trees
python -m chabadtrees calibrate            # בדיקת חיבור + הדפסת תיעוד התבניות ושדות תבניות האישים
python -m chabadtrees all --png            # fetch → extract → graph → existing → render
```

או שלב-שלב:

```bash
python -m chabadtrees fetch                # איסוף כל ערכי האישים (ניתן להמשך; כשלים מנוסים שוב)
python -m chabadtrees extract [--llm]      # חילוץ קשרים (אופציונלי: גם בעזרת Claude)
python -m chabadtrees resolve              # כל יעד קישור → שם הערך הקנוני (הפניות נפתרות, דפים חסרים מסומנים)
python -m chabadtrees graph                # מיזוג, הצלבה, הסקות, חלוקה למשפחות
python -m chabadtrees existing             # אילו משפחות כבר יש להן עץ באתר
python -m chabadtrees render --png         # קוד ויקי + תצוגה מקדימה + דף בדיקה
python -m chabadtrees render --root "רבי פלוני" --max-depth 3      # עץ צאצאים מאדם מסוים
python -m chabadtrees render --ancestors-for "רבי פלוני"           # עץ אבות לאדם מסוים
```

### הרצה ב-GitHub Actions (בלי מחשב מקומי)

ה-workflow `build-trees` (Actions → build-trees → Run workflow) מריץ את הצינור בשרתי GitHub, שיש להם גישה לאתר, ומפרסם את התוצאות בענף `results`: `results/output/` (העצים, התצוגות, דף הבדיקה), `results/calibrate.txt`, `results/run.log` ו-`results/summary.json`. מטמון הדפים נשמר בין ריצות, ו-`data/` המלא נשמר כארטיפקט לשבעה ימים.

| קלט | משמעות |
|---|---|
| `mode` | `all` (ברירת מחדל) · `calibrate` (רק כיול) · `render` (בנייה מחדש מהמטמון בלי משיכה) |
| `limit` | מגבלת דפים למשיכה, לבדיקה מהירה |
| `family` | לבנות בנוסף רק משפחות שהתווית שלהן מכילה טקסט זה (הפלט ב-`results/output/family/`) |
| `root` | עץ צאצאים מאדם מסוים (הפלט ב-`results/output/root/`) |
| `categories` | קטגוריות שורש במקום "אישים", מופרדות בפסיק (למשל `משפחת רסקין`) |
| `png` | `true` – גם צילומי PNG של כל העצים (איטי: כ-3 שניות לעץ). התצוגה המקדימה ב-HTML נוצרת תמיד |

הרצה בסביבת ענן של Claude Code: הסביבה חייבת לאפשר גישה ל-`chabadpedia.co.il` (Network access = Custom, להוסיף את הדומיין ואת `www.chabadpedia.co.il` לרשימה). בלי זה `fetch` ייכשל מיד.

## איך זה עובד

1. **fetch** – עובר על עץ הקטגוריות מ"אישים" (עומק עד 8), ומושך את הוויקיטקסט של כל דף ב-50 דפים לבקשה. עץ הקטגוריות מכיל גם ספרים, ניגונים, חסידויות ואירועים (למשל הקטגוריה "אדמו"ר הזקן" כוללת את ספריו וניגוניו) – `chabadtrees/persons.py` מסווג כל דף לפי הקטגוריות והכותרת שלו, ורק דפי אישים (כ-5,500 מתוך כ-6,600) נכנסים לחילוץ וללקסיקון השמות. מכבד `maxlag`, שולח User-Agent מזהה, ומאט את הקצב אחרי כל 429. כל דף שנכשל נרשם ב-`data/fetch_state.json` עם השגיאה, מנוסה שוב בסוף הריצה ובריצה הבאה (הכשלים נכנסים ראשונים לתור), ואם משהו עדיין חסר הפקודה מסתיימת בקוד 2 ומדפיסה כמה. דפים חסרים (הפניות שבורות) נרשמים בנפרד. הרצה חוזרת לא מושכת דפים שכבר במטמון (`--refresh` לרענון).
2. **extract** – שלוש שכבות: שדות המשפחה בתבנית האישיות, קטגוריות "משפחת X", ודפוסי משפט בעברית ("בנו של", "נולד לאביו X ולאמו Y", "נשא לאישה את", "חתנו של", "סבו מצד אביו", רשימות תחת "ילדיו:" וכו'). הנושא של כל ביטוי נקבע מהטקסט שלפניו: "[[X]], בנו של [[Y]]" מדבר על X; "היה חתנו של [[A]], בעלה של [[B]]" – הנושא הוא הערך, כי A הוא מושא. שרשראות יוחסין ("בנו של Y, בנו של Z") נפתרות נכון. כינויים ("הצמח צדק", "הרבי") נפתרים לערך רק אם הם ייחודיים; שמות פרטיים בלי שם משפחה לא נפתרים לעולם (יש הרבה "דבורה לאה"). "בתו חנה נישאה ל[[X]]" – הנושא הוא חנה (והיא נרשמת כבת), לא הערך. שם לא-מקושר מתקבל רק אם המילה הראשונה שלו היא שם פרטי המוכר מכותרות הערכים (או באה אחרי תואר), וההמשך נגזר במילה שכיחה בקורפוס שאינה שם ("חנה מפעילה פעילות" → "חנה"; "שימשה כמחנכת" → כלום; "יעקב אמסעל" נשמר כי "אמסעל" נדיר). "אסתר למשפחת וולף" → "אסתר לבית וולף". תאריכים עבריים ("כ' במנחם אב") וקישורים לדפים קיימים שאינם דפי אישים אינם אנשים. לכל קשר נשמרים המשפט המקורי, ה-`<ref>` שצמודים לו, הדף והדפוס.
3. **resolve** – כל יעד `[[קישור]]` שהופיע בקשר ואינו דף שנמשך נשאל מול האתר עם `redirects=1`: הפניה (למשל "(אב הרבי)") מוחלפת בשם הערך האמיתי, ודף שלא קיים מסומן כך שהאדם יוצג בלי קישור. כך הקישורים בעץ הם תמיד לשם הערך כפי שהוא באתר.
4. **graph** – מיזוג הקשרים: קשר שמופיע בשני ערכים מקבל דגל `corroborated` וביטחון גבוה יותר; אנשים בלי ערך ממוזגים רק כשהשמות תואמים (שווים, תחילית – "חנה"/"חנה ליבא", או שגיאת כתיב – "חי שרה"/"חיה שרה") וגם יש להם אותה משבצת משפחתית: בת זוג של אותו אדם, ילד של אותו הורה, או אם של ילדו (ולכן בת זוגו) – כך סבתא ונכדה בעלות אותו שם נשארות נפרדות, ו"בנו נטע שלמה" מתמזג לערך "נטע שלמה וילהלם"; הסקות (אחים חולקים הורים, חתן ⇒ בן זוג של הבת) מסומנות `inferred`; סתירות (שני אבות, הורה שנולד אחרי הילד) מסומנות ומורידות ביטחון.
5. **existing** – מאתר עצים קיימים בשלוש דרכים (קטגוריית "עצי משפחה", דפים שמשבצים את תבניות העץ, חיפוש כותרות "עץ משפחת"), קורא מי מופיע בכל עץ ואילו דפים מציגים אותו, ומדווח לכל משפחה: קיים / חלקי / אין.
6. **render** – עץ לכל קטגוריית "משפחת X" (ולכל רכיב קשרים גדול שלא מכוסה). ילד מוצג תחת ההורה שיש לו ערך (ואם לשניהם – תחת האב). מי שהתחתן לתוך המשפחה (אין לו הורים בה ובן זוגו צאצא שלה) מופיע רק בתוך הקופסה של בן הזוג, והוריו לא נכנסים לעץ. זוג השורש בשתי קופסאות (`A |ד| B`, כמו בתיעוד התבנית), ובני הזוג של הצאצאים בתוך הקופסה, כמו בעצים הקיימים באתר; אם לבן הזוג יש עץ משפחה משלו באתר, מתווסף קישור אליו. הצומת ממוקם מעל הילד האמצעי (`+`) או בין שני האמצעיים (`^`). גודל עץ מוגבל כמו העצים הקיימים באתר (עד 45 בני משפחה ועד 64 מרצפות רוחב – העצים באתר הם עד ~63): עץ גדול מזה מתפצל – הענף הגדול ביותר ("צאצאי X") הופך לעץ נפרד `תבנית:עץ משפחת ... – צאצאי X`, ובעץ הראשי נשארת הקופסה של X עם קישור אליו, כמו שנעשה באתר לבית רבי. **פרטיות (ברירת מחדל):** מי שאין לו ערך אינו מופיע בעץ בכלל – לא כקופסה, לא כ"אשתו: X" ולא ברשימת ילדים (`include_unlinked: false`). חריגים: אדם בלי ערך שבלעדיו צאצאים עם ערך היו מתנתקים מהעץ (אב בלי ערך של שני בנים עם ערך) מופיע כקופסה בלי שם ("אב (ללא ערך)"), ובת/בן בלי ערך שנשוי/אה למי שיש לו ערך מופיע/ה כ"בת (ללא ערך)" עם "אשת [[החתן]]" – כך החתנים של המשפחה נשארים בעץ. "חתנו [[X]]" בלי שם הבת יוצר בגרף בן/בת בלי שם (מסומן/ת `virtual`) שמחבר/ת בין החותן לחתן. קישור אדום (שם מקושר שאין לו ערך) נחשב כמי שאין לו ערך. בן/בת זוג בלי ערך שלהורהו יש ערך נזכר/ת בלי שם: "אשתו: בת [[האב]]". כשבן הזוג (או אביו) מופיע בעץ אחר – שנבנה כאן או שכבר קיים באתר – מתווסף "(עץ משפחת X)" עם קישור, בשני הכיוונים. אם להורה של בן הזוג אין ערך אבל לאח/ות שלו יש – "אשתו: אחות [[X]]". "גיסו, הרב X" שכתוב בערך מוצג בקופסה ("גיסו: [[X]] (עץ משפחת X)") – בלי לנחש מי מהאחים נשוי למי. אב ואם של אותו ילד נחשבים בני זוג (הסקה). שם מלא של גבר בלי ערך שמופיע בגרף בדיוק פעמיים – פעם כבן ("בנו ר' X") ופעם כבעל ("בתו, אשת ר' X" בדף חותנו) – מתאחד לאדם אחד, גם כשבאחד מהם חסר שם אמצעי ("אריה הרטמן" / "אריה אברהם הרטמן"), רק לשמות משפחה נדירים (עד 15 ערכים), כדי לא לאחד בני דודים שקרויים על שם אותו סב. אזכור עם שם אמצעי ("הרב אפרים צבי לרר") מתאחד עם הערך בלי השם האמצעי ("אפרים לרר") באותם תנאים, והראיות מסומנות כפתרון-שם (חלשות). שם פרטי שלא מופיע בשום כותרת מתקבל כשאחריו שם משפחה מוכר ("מתיה לרר").

**שמות חוזרים:** אזכור בשם-תצוגה שנפתר לערך ("בנו של משה בלוי") נבדק מול הערך: אם הערך כבר יש לו אב מפורש אחר, או שהשנים לא מסתדרות (ילד או נכד שנולד לפני ה"הורה", הורה שנפטר לפני הלידה), האזכור מופרד מהערך וחוזר להיות אדם בלי ערך – על כל הקשרים שנפתרו מאותו דף – והמיזוג הרגיל מוצא לו את המשבצת הנכונה (למשל משה אורי בלוי, בן יצחק שלמה, ולא הסופר משה בלוי בן תשי"ב). שרשרת "בנו של X בנו של Y" נקראת כשרשרת גם כש-X בלי קישור.

**משיכה חוזרת:** הריצה שומרת את הדפים במטמון; בכל ריצה נמשכים מחדש רק דפים שנערכו או נוצרו באתר מאז הבדיקה הקודמת (`list=recentchanges`), כך שעריכה בערך נכנסת לעץ בריצה הבאה. `refresh: true` בהפעלה (או `--refresh`) מושך את הכול מחדש. עם `include_unlinked: true` כולם מוצגים, וילד בלי ערך שידוע רק בשמו הפרטי מוצג כטקסט בקופסת ההורה ("ילדים: חנה, רבקה").

## כיול מול האתר החי (בהרצה הראשונה)

`python -m chabadtrees calibrate` מדפיס את מה שצריך. הדברים שהם ניחוש ב-`chabadtrees/config.py` ואפשר לדרוס ב-`config.json`:

| מפתח | מה לבדוק |
|---|---|
| `chart.symbols` | סמלי המרצפות של `תבנית:עץ משפחה`, נגזרו מקוד התבנית עצמו: `!` אנכי, `-` אופקי, `~` מקווקו (נישואין), `ד` צומת נישואין, `ז` T למטה, `^` T למעלה, `+` הצטלבות, `)`/`(` T לצדדים, `.` `,` `'` `` ` `` פינות. תיבת טקסט תופסת 3 מרצפות והקווים מתחברים למרצפת האמצעית שלה (`box_tiles`) |
| `chart.spouse_style` | `inline` (ברירת מחדל, כמו באתר): בת מוצגת "שם, אשת [[בעלה]]" ובן "אשתו: [[...]]" בתוך הקופסה; `boxes`: קופסה נפרדת לכל בן זוג. זוג השורש תמיד בשתי קופסאות `A ~ ד ~ B` |
| `chart.mirror_horizontal` | אם בתצוגה החיה הפינות יוצאות הפוכות – להפוך ל-`true` |
| `chart.start/row/end` | שמות תבניות ההתחלה/שורה/סוף |
| `ahnentafel.params` | שמות הפרמטרים של `עץ משפחה לאדם אחד` |
| `infobox_fields` | שמות שדות המשפחה בתבנית האישיות (הפקודה מדפיסה שדות שנראים כמו שדות משפחה ולא זוהו) |
| `person_root_categories`, `exclude_categories` | מאיפה אוספים אישים ומה מדלגים |

## העלאה לאתר

עריכות המוניות בחב"דפדיה דורשות תיאום עם הקהילה (יש לאתר עמוד מדיניות בוטים ואולם דיונים לבוטים). המסלול המומלץ: להעלות ידנית 2–3 עצים לדוגמה לאולם הדיונים, לקבל אישור ודגל בוט, ורק אז:

```bash
python -m chabadtrees upload --file "output/trees/עץ משפחת פלוני.wiki" --title "תבנית:עץ משפחת פלוני"                 # הרצה יבשה
CHABADPEDIA_USER=... CHABADPEDIA_PASSWORD=... python -m chabadtrees upload ... --yes --i-have-community-approval
```

## חילוץ בעזרת Claude (אופציונלי)

`extract --llm` שולח כל ערך ל-Claude (`claude-opus-5` כברירת מחדל, עם fallback אוטומטי) ומבקש JSON של קשרים עם המשפט המדויק לכל אחד. התוצאות נשמרות ב-`data/llm_cache.json` לפי גרסת הדף, כשלים נרשמים ומנוסים שוב. דורש `pip install anthropic` ומפתח API. על 5–6 אלף ערכים זה כמה עשרות דולרים.

## בדיקות

```bash
python -m unittest tests.test_all -v
```

הבדיקות מרימות שרת API מדומה (`tests/mock_api.py`) עם 44 דפי דוגמה (`tests/fixtures/`), ובודקות בין השאר הרצה מלאה, זיהוי עץ קיים, עמידות ב-429 (אף דף לא נעלם) והמשך אחרי כשל קשיח.

## מבנה

```
chabadtrees/
  api.py        לקוח מדיה-ויקי: קצב, maxlag, 429/Retry-After, ניסיונות חוזרים, משיכה ב-50

  graph.py      מיזוג, הצלבה, הסקות, בדיקות עקביות, משפחות
  layout.py     עץ צאצאים על גריד (Tree chart) ועץ אבות
  render.py     קוד ויקי; preview.py – HTML/PNG; review.py – דף בדיקה
  existing.py   איתור עצים קיימים וכיסוי
```
